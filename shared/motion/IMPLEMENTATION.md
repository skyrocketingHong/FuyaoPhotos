## Photo and state boundaries

Cards, Metadata and Colors offer a close action. Dirty sessions keep their discard confirmation. Closing clears only the owning private editing session; originals and exported files are preserved. Shared photo pages resolve the actual session owner. Replacing photos first decodes a usable new preview, then publishes the replacement and emits the old image's departure. Cancellation and failed preparation retain the old session and metadata drafts.

Particle frames are independent SDR copies. Native HDR presentation and export resources are not flattened. Current zoom, pan, depth presentation and the information-card overlay are retained. The previous image stays visible until the GPU's first frame. The data operation does not wait for the animation. Reduced motion, backgrounding, disposal and deadlines release visual resources. Android replacement events follow the current UI host after activity recreation; stale metadata saves cannot restore a discarded draft.

On Apple platforms, photo departures carry an owner, a single consumption ticket and an absolute monotonic deadline. A close action passes its capture owner explicitly; replacement events retain eligible-capture selection. Only the selected, visible photo page registers a capture or consumes its event. A root-tab change cancels visual events synchronously, and returning to a retained tab cannot start an old event again. A native renderer can be created only once for the copy. Multiple-window interaction remains a separate device acceptance check.

Each safe backdrop layer registers separately with priority and coordinates. Only the SDR ambient background and ordinary controls/lists are sampled. Metadata and color value lists can scroll behind the bottom bar, with content padding keeping their last actions reachable. Fixed photos, current-pixel summaries and selectors remain above the bar. Insets are consumed once.

## Close-to-placeholder reassembly

Closing a photo creates a visual request, then immediately continues the real session cleanup. The source copy stays visible while the destination is prepared. The target is the actual Cards, Metadata or Colors import card for the initiating page, independently of which shared session owns its data.

- Android records the normal `PhotoImportCard` drawing into a `GraphicsLayer` and captures its measured root bounds after a ready frame. It waits for `busy == false`, so cleanup's temporary loading state is not used as the destination. The card is recorded before its final drawing is withheld; it is not captured with zero alpha or disabled controls. Metadata registers the visible bitmap on the stable viewport and updates its geometry directly from layout callbacks. Hardware bitmaps are copied before software snapshot composition without modifying the original.
- Apple renders the same `PhotoImportForm` used by the live page in a hidden native capture host. A shared appearance modifier copies public writable traits, including color scheme, locale, Dynamic Type, display scale and macOS control activity; it does not replace the host's complete SwiftUI environment. System contrast and reduced transparency are tracked for invalidation and inherited from the native host. Comparing against the empty native Form identifies the section surface around the measured content, including native insets and corners. It does not substitute a hand-drawn rectangle. The request, capture attempt, appearance and live content bounds must still match when the result arrives. Hidden actions keep their enabled appearance, while action guards, shortcuts, focus, hit testing and accessibility prevent interaction.

Both paths use an 880 ms analytic transition, a 650 ms target-capture deadline and a 2400 ms total request lifetime. A grid starts from 3 logical-unit cells and is capped at 24,000 particles. Scatter reaches its peak over `t = 0...0.22` with `cubic-bezier(0.23, 1, 0.32, 1)`. Travel accelerates and then settles over `t = 0.22...0.90` with `cubic-bezier(0.77, 0, 0.175, 1)`; scatter retreats as `1 - travel`. The same travel curve mixes premultiplied source/target textures over `t = 0.35...0.88`. Cell size follows the source/target geometry and contracts by `1 - 0.55 * scatter`. CPU code solves the Bezier time coordinate once per frame and passes weights to the shaders. At `t = 0` the source is exact; from `t = 0.90` onward the target position, texture and cell size are exact and remain fixed for the final 88 ms. Endpoint vertices map UVs directly into their rectangle to avoid cancellation error from subtracting particle centers.

The native destination's input and accessibility are hidden until handoff. Android places `focusProperties` before `focusGroup`, so `onEnter` blocks entry at the group's focus target. Android starts the GPU view hidden and uses one draw gate to select the source copy, presented GPU frame or fixed target bridge. After `SurfaceTexture` observes the terminal EGL presentation timestamp, the bridge is drawn before stopping the GPU. The live target then records a normal native layer and confirms the same request, owner, bounds and appearance before replacing the bridge in the same draw pass. This keeps translucent pixels from being composited twice. Cancellation hides and stops the matching GPU immediately. Apple removes the completed GPU copy and reveals the unchanged native card in one main-actor transaction with animations disabled. Neither path adds a second fade. A canvas-height change during keyboard dismissal updates the viewport instead of blindly ending playback; actual target relayout, cancellation, a new import, backgrounding, reduced motion, capture failure, renderer failure or expiry falls back to the native placeholder. Navigation and picker/import entry points cancel synchronously, including permission and package-import paths. Stale generations and capture attempts cannot replace or finish a newer request.

## Shared parameters and verification

`tokens.json` and `scripts/generate-motion-tokens.py` retain common control/progress timing, snapshot limits and the Fuyao reassembly contract. Both build scripts check the generated Kotlin/Swift constants. The preserved dust paths still use their original platform shader physics.

Source-hash tests verify the imported shaders. Reassembly tests use the shared `reassembly-progress.json` high-precision reference samples and dense progress checks for monotonic travel, bounded scatter, acceleration, settling speed and a stationary terminal phase, alongside grid limits, stale requests and deadlines. Apple tests include offscreen Metal initialization, update bounds, lifetime, image orientation and alpha; hosts without a Metal device explicitly skip GPU tests. Android device tests include ES 3 endpoint readback for rectangle placement, texture orientation and premultiplied alpha, plus hardware-bitmap snapshot handling. Compiling those tests does not execute Android GPU rendering. Existing source-pixel decoding and replacement-safety regressions remain. Source color readouts keep original floating-point components; explicit spaces convert the same sample, with only 8-bit RGB/HEX clipped.

Original particle licenses are in `LICENSES/`. Navigation versions, authors, adaptations and licenses are in `third_party/AndroidNavigation/`, with Android notices included in the APK. Device visual fidelity, Android GPU execution, gestures, accessibility and frame pacing remain separate acceptance checks.
